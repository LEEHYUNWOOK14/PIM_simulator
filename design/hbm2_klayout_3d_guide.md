# HBM2 + Logic Die KLayout 3D 관찰 설명서

## 1. 이 화면이 나타내는 것

이 화면은 `output/output.gds`에서 읽은 실제 로직 RTL 배선과, HBM2 패키지를
이해하기 위해 생성한 패키지 수준 형상을 하나의 KLayout 2.5D 장면으로 결합한
것이다.

- `Logic RTL / ...` 항목은 OpenROAD를 거쳐 생성된 실제 GDS 형상이다.
- DRAM 다이, TSV, 마이크로범프, 인터포저와 thermal lid는 구조 및 배치 검토를
  위한 파라미터 기반 대표 모델이다.
- 대표 모델의 치수와 개수는 `design/hbm2_package.json`에서 변경할 수 있다.
- 이 장면은 구조와 연결 관계를 보는 모델이며, 열 해석이나 SI/PI signoff 결과가
  아니다.

## 2. 실행 방법

저장소 최상위 PowerShell 터미널에서 다음 명령을 실행한다.

```powershell
.\tools\open_hbm2_logic_3d.cmd
```

KLayout의 기본 2D GDS 창과 `2.5d View` 창이 열린다. 구조 관찰에는 `2.5d View`
창을 사용한다.

## 3. 기본 조작법

| 조작 | 기능 |
|---|---|
| 마우스 오른쪽 버튼 드래그 | 3D 구조 회전 |
| 마우스 가운데 버튼 드래그 | 화면 평행 이동 |
| 마우스 휠 | 확대 및 축소 |
| 범례 왼쪽 체크박스 | 해당 재료 또는 레이어 표시/숨김 |
| 범례의 색상 사각형 | 레이어 색상 식별 |
| 상단 `X` 값/슬라이더 | 수평 크기 비율 조절 |
| 상단 `Z` 값/슬라이더 | 높이 방향 강조 비율 조절 |

전체 스택이 화면 밖으로 나가 있으면 먼저 마우스 휠로 충분히 축소한다. HBM의
가로·세로 길이는 수천 um이고 전체 적층 높이는 수백 um이므로, 실제 비율에서는
높이가 얇게 보이는 것이 정상이다. DRAM 다이 사이 간격이나 금속층을 보기 위해
`Z` 배율을 높일 수 있지만, 이 경우 화면상의 높이는 실제 종횡비가 아니다.

## 4. 권장 관찰 순서

1. 모든 레이어를 켜고 오른쪽 드래그로 전체 적층 구조를 비스듬히 본다.
2. `Thermal lid perimeter`를 끄고 DRAM 다이 8개를 확인한다.
3. DRAM 다이를 위에서부터 하나씩 끄며 `Representative TSV columns`를 확인한다.
4. DRAM 다이를 모두 끄고 `Representative microbump array`를 확인한다.
5. `HBM2 base logic die`를 끄거나 시야를 확대하여 실제 `Logic RTL` 금속층을 본다.
6. `MET5`부터 `LI1` 방향으로 하나씩 끄며 상부 배선과 하부 로컬 배선의 차이를
   관찰한다.

## 5. 범례 항목 설명

### Package substrate / interposer

HBM 스택을 시스템 패키지 또는 다른 칩과 연결하는 하부 지지·배선 구조다. 전원,
접지, 외부 데이터 신호가 이 층을 통해 전달된다. 현재 모델에서는 전체 HBM 구조의
기준 면적과 하부 열 경로를 나타낸다.

관찰할 때는 가장 아래쪽의 넓은 판으로 보면 된다. 로직 다이보다 넓기 때문에 패키지
여유 면적과 외부 연결 공간을 가늠할 수 있다.

### HBM2 base logic die

DRAM 다이 아래에 위치하는 베이스 로직 다이다. DRAM 채널 인터페이스, 명령 및 주소
분배, 데이터 입출력 경로와 이 프로젝트의 PIM reduction 로직이 위치할 후보 영역이다.

현재 `output.gds`는 전체 베이스 다이 구현이 아니라 로직 블록 하나의 구현 결과다.
따라서 넓은 base logic die 안에 실제 RTL 블록이 배치되는 형태로 표현된다.

### Logic RTL / LI1

`LI1`은 SKY130의 local interconnect다. 표준 셀 내부 또는 매우 가까운 소자 사이의
짧은 연결에 사용된다. 트랜지스터와 하부 금속 배선을 이어 주는 로컬 연결층으로
이해하면 된다.

### Logic RTL / MCON

`MCON`은 LI1과 MET1을 수직으로 연결하는 콘택트다. 평면 배선층이 아니라 두 높이
사이를 잇는 작은 수직 연결 구조다.

### Logic RTL / MET1

첫 번째 일반 금속 배선층이다. 표준 셀 내부 연결과 짧은 거리의 로컬 신호 배선이
많이 나타난다. 확대하면 다른 상부 금속층보다 조밀한 패턴으로 보일 수 있다.

### Logic RTL / VIA1

MET1과 MET2 사이의 수직 접속이다. 신호가 배선 방향이나 금속층을 바꿀 때 사용된다.
비아가 집중된 위치는 층간 연결과 라우팅 복잡도가 높은 지점일 수 있다.

### Logic RTL / MET2

두 번째 금속 배선층이다. MET1과 다른 우선 배선 방향을 사용해 교차 라우팅을
가능하게 한다. MET1과 함께 로컬 및 중간 거리 신호망을 구성한다.

### Logic RTL / VIA2

MET2와 MET3를 연결하는 수직 접속이다. MET3로 올라가는 신호와 전원망의 연결
위치를 보여 준다.

### Logic RTL / MET3

중간 금속 배선층이다. 하부의 셀 중심 배선보다 긴 거리의 신호, 블록 내부 분배 및
일부 전원 연결에 활용된다.

### Logic RTL / VIA3

MET3와 MET4를 연결한다. 상부의 비교적 굵고 긴 배선으로 신호나 전원을 전달하는
통로다.

### Logic RTL / MET4

상부 금속 배선층이다. 하부 금속보다 긴 전역 배선과 전원 분배에 유리하다. 이 층을
단독으로 켜면 로직 블록 전체를 가로지르는 배선 구조를 관찰하기 쉽다.

### Logic RTL / VIA4

MET4와 최상부 MET5를 연결한다. 상부 전원망 또는 장거리 배선으로 올라가는 수직
연결 지점이다.

### Logic RTL / MET5

현재 SKY130 스택에서 표시하는 최상부 금속층이다. 전원 및 접지 분배처럼 폭이 넓고
긴 배선에 적합하다. 패키지 접속이나 상위 인터페이스를 설계할 때 접근하기 가장 좋은
금속층이지만, 현재 GDS에는 완성된 HBM PHY 및 마이크로범프 재배선망이 포함되어
있지 않다.

### Representative microbump array

베이스 로직 다이와 가장 아래쪽 DRAM 다이를 연결하는 미세 범프 배열의 대표
형상이다. 데이터, 명령, 주소, 전원 및 접지 신호가 이 수직 접속을 통과한다.

화면의 범프 개수는 구조를 읽기 쉽게 만든 대표 배열이며 실제 HBM2 범프 맵이나
1024-bit 데이터 인터페이스의 정확한 핀 배치를 의미하지 않는다.

### HBM2 DRAM die 0 / 8 channels

베이스 로직 다이에 가장 가까운 첫 번째 DRAM 다이다. `/ 8 channels`는 한 DRAM
다이의 평면을 8개 채널 영역으로 나누어 표시했다는 뜻이다. 중앙 또는 채널 사이의
검은 틈은 채널 경계를 읽기 위한 시각적 간격이다.

### HBM2 DRAM die 1 / 8 channels

아래에서 두 번째 DRAM 다이다. die 0과 TSV 및 다이 사이 접속으로 연결된다.

### HBM2 DRAM die 2 / 8 channels

아래에서 세 번째 DRAM 다이다. 서로 다른 색은 전기적 재료 차이가 아니라 적층
순서를 쉽게 구분하기 위한 색상이다.

### HBM2 DRAM die 3 / 8 channels

아래에서 네 번째 DRAM 다이다. die 0~3만 켜면 4단 HBM 스택과 유사한 구조를
비교 관찰할 수 있다.

### HBM2 DRAM die 4 / 8 channels

아래에서 다섯 번째 DRAM 다이다. 상부 다이가 추가될수록 로직 다이까지의 열 및
수직 연결 경로가 길어진다.

### HBM2 DRAM die 5 / 8 channels

아래에서 여섯 번째 DRAM 다이다. TSV는 이 다이를 관통해 위아래 다이와 연결된다.

### HBM2 DRAM die 6 / 8 channels

아래에서 일곱 번째 DRAM 다이다. 상부에 가까워질수록 로직 다이와의 물리적 거리는
늘어나지만, TSV 기반 연결이므로 수평 배선보다 짧은 수직 경로를 유지한다.

### HBM2 DRAM die 7 / 8 channels

가장 위쪽의 여덟 번째 DRAM 다이다. 열이 위쪽 lid로 빠져나가는 경로와 아래쪽 로직
다이에서 올라오는 열의 영향을 함께 검토해야 하는 위치다.

### Representative TSV columns

TSV(Through-Silicon Via)는 실리콘 다이를 수직으로 관통하는 도전성 연결이다. 적층된
DRAM 다이 사이에서 데이터, 명령, 주소, 전원 및 접지를 전달한다.

현재 화면은 구조 확인을 위한 대표 TSV 열만 표시한다. 실제 TSV 개수, 직경, keep-out
zone과 신호 배치는 제조 공정 및 HBM PHY 설계 데이터가 필요하다. TSV 주변은 회로를
배치하기 어려운 keep-out 영역과 열·응력 비용이 발생할 수 있으므로 로직 위치 최적화
시 중요한 제약이다.

### Thermal lid perimeter

스택 상부의 열 확산판 또는 lid 외곽을 나타낸다. 내부를 막힌 판으로 만들지 않고
테두리만 표시해 DRAM 다이를 계속 볼 수 있게 했다. 실제 제품에서는 TIM과 heat
spreader를 통해 열을 방열 구조로 전달한다.

## 6. 전체 작동 원리

일반적인 데이터 이동 방향은 다음과 같다.

```text
DRAM cell/array
    -> DRAM die 내부 채널 회로
    -> TSV
    -> 최하부 DRAM die
    -> microbump
    -> HBM2 base logic die
    -> PHY/채널 인터페이스
    -> PIM reduction RTL 후보
    -> 상부 금속 및 패키지 인터페이스
```

1. 각 DRAM 다이는 데이터를 저장하고 채널 단위로 명령과 데이터 전송을 처리한다.
2. 적층 다이의 신호는 TSV를 통해 수직 방향으로 이동한다.
3. 최하부 DRAM 다이와 베이스 로직 다이는 마이크로범프로 연결된다.
4. 베이스 로직 다이는 채널 신호를 수집하고 외부 인터페이스 또는 PIM 로직으로
   전달한다.
5. 이 프로젝트의 RTL은 채널 및 bank에서 생성된 partial result를 모아 reduction하고,
   공유 출력 링크로 내보내는 로직 다이 후보 구조다.

## 7. 로직 위치를 볼 때 확인할 항목

### 배선 비용

- 로직 블록에서 microbump/TSV 접속 영역까지의 수평 거리
- MET4/MET5 장거리 배선의 길이와 혼잡도
- 채널별 경로 길이 편차
- 비아 개수와 층 전환 횟수

### 열 비용

- 로직 블록의 연산 밀도와 예상 전력 밀도
- TSV 및 금속층을 통한 수직 열 경로
- DRAM hot spot과 로직 hot spot의 중첩
- die edge, thermal lid 및 인터포저 방향 방열 거리

### 면적 및 제조 비용

- TSV keep-out zone과 로직 영역의 충돌
- microbump pitch와 필요한 I/O 개수
- base logic die 면적 증가량
- 전원망, decap, clock tree 및 PHY 예약 면적
- 다이 크기 증가에 따른 수율 저하 가능성

## 8. 로직 블록 위치 변경

`design/hbm2_package.json`의 다음 값을 um 단위로 변경한다.

```json
"logic_block_x_um": 0,
"logic_block_y_um": 0
```

- 양의 X: 화면의 오른쪽 방향
- 음의 X: 화면의 왼쪽 방향
- 양의 Y: 화면의 위쪽 방향
- 음의 Y: 화면의 아래쪽 방향

변경 후 KLayout을 닫고 `open_hbm2_logic_3d.cmd`를 다시 실행한다. 실제 GDS 형상은
확대하거나 변형하지 않고 지정한 위치로 평행 이동한다.

## 9. 해석 시 주의사항

- 현재 RTL GDS는 전체 HBM2 베이스 다이나 완성된 HBM PHY가 아니다.
- DRAM 다이와 패키지 치수는 `hbm2_package.json`에 기록된 설계 가정이다.
- 마이크로범프와 TSV는 대표 형상이며 실제 pin map이 아니다.
- KLayout 2.5D의 색은 재료의 실제 색, 전기 특성 또는 온도를 뜻하지 않는다.
- 실제 열 분석에는 전력 맵, 재료별 열전도도, TIM, 경계 조건과 HotSpot/ANSYS 같은
  해석 도구가 필요하다.
- 실제 하드웨어 비용 산정에는 PDK 패키지 규칙, PHY 면적, SI/PI, DRC, LVS와 제조사
  데이터를 추가해야 한다.
