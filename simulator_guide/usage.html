PIMSimulator 사용방법

이 문서는 이 저장소를 처음 보는 사람이 실제로 시뮬레이터를 돌릴 수 있도록 만든 실전 안내서입니다. 설치, 빌드, 테스트 실행, 설정 파일 조정, 디버그 출력, 자주 만나는 오류까지 한 흐름으로 정리했습니다.

1. 이 시뮬레이터가 무엇인지 먼저 이해하기

이 프로젝트는 HBM2 기반 Processing-in-Memory, 즉 PIM 동작을 C++로 시뮬레이션하는 코드입니다. 화면이 있는 앱이 아니라, sim이라는 실행 파일을 만들어서 터미널에서 테스트를 돌리는 구조입니다.

편집 도구 VSCode는 코드를 보기 좋게 편집하는 용도입니다.
실행 도구 실제 시뮬레이션은 터미널에서 ./sim으로 실행합니다.
확인 방법 결과는 콘솔에 PASS/FAIL, cycle 수, speed-up 같은 텍스트로 출력됩니다.

2. 준비해야 할 것

  1. Ubuntu 또는 WSL2 환경
  2. scons
  3. libgtest-dev
  4. C++ 컴파일러, 보통 g++
sudo apt update
sudo apt install scons libgtest-dev

저장소의 과거 빌드 기록을 보면 Ubuntu 26.04 LTS + g++ 15.2 + SCons 4.8 환경에서 정상 빌드된 흔적이 있습니다.

3. 저장소 구조를 빠르게 잡는 법

src/tests/KernelTestCases.cpp - 어떤 테스트를 돌리는지 정리된 시작점
src/tests/PIMKernel.cpp - PIM 연산 실행 흐름의 핵심
src/PIMCmd.* - PIM 명령어 인코딩과 생성
src/MemorySystem.* - 메모리 시스템의 진입점
src/PIMRank.* - PIM 모드 전환과 CRF 실행
system_hbm.ini - 실제 실험에 많이 쓰는 설정 파일
처음에는 코드 전체를 한 번에 이해하려 하지 말고, KernelTestCases.cpp에서 테스트 이름을 확인한 뒤 PIMKernel.cpp로 내려가는 방식이 가장 편합니다.

4. 빌드하는 방법

프로젝트 루트에서 아래 명령을 실행합니다.

scons

빌드가 성공하면 다음이 생성됩니다.

  • sim - 실제 실행 파일
  • bin/ - 중간 객체 파일
  • libdramsim/dramsim2 - 라이브러리 산출물

옵션 빌드도 가능합니다.

scons NO_STORAGE=1
scons NO_EMUL=1
scons NO_LIBRARY=1
주의: 일부 옵션은 검증 코드나 Emulator API를 빼는 설정입니다. 처음에는 기본 scons로 빌드하는 것이 가장 안전합니다.

5. 테스트 목록 확인하기

빌드 후 다음 명령으로 실행 가능한 테스트 이름을 볼 수 있습니다. 

./sim --gtest_list_tests

현재 확인된 주요 테스트는 다음과 같습니다.

  • PIMKernelFixture.gemv_tree
  • PIMKernelFixture.gemv
  • PIMKernelFixture.mul
  • PIMKernelFixture.add
  • PIMKernelFixture.relu
  • MemBandwidthFixture.hbm_read_bandwidth
  • MemBandwidthFixture.hbm_write_bandwidth
  • PIMBenchFixture.gemv
  • PIMBenchFixture.mul
  • PIMBenchFixture.add
  • PIMBenchFixture.relu

6. 처음 실행할 때 추천 순서

  1. 가벼운 기능 확인: ./sim --gtest_filter=PIMKernelFixture.gemv
  2. 다음 기능 확인: ./sim --gtest_filter=PIMKernelFixture.add
  3. 성능 실험: ./sim --gtest_filter=PIMBenchFixture.gemv
  4. 대역폭 확인: ./sim --gtest_filter=MemBandwidthFixture.hbm_read_bandwidth
./sim --gtest_filter=PIMKernelFixture.gemv
./sim --gtest_filter=PIMKernelFixture.mul
./sim --gtest_filter=PIMKernelFixture.add
./sim --gtest_filter=PIMKernelFixture.relu
기능 테스트는 “정확히 계산되는가”를 보는 쪽이고, 벤치마크 테스트는 “PIM이 얼마나 빨라지는가”를 보는 쪽입니다.

7. 설정 파일을 어떻게 바꾸는가

실험에서 가장 자주 바꾸는 것은 채널 수, 주소 매핑, 디버그 출력, PIM 정밀도입니다. 기본적으로는 system_hbm.ini를 기준으로 시작합니다.

NUM_CHANS 채널 수를 바꿉니다. 1채널, 16채널, 64채널 실험이 가능합니다.
ADDRESS_MAPPING_SCHEME PIM 기능은 보통 Scheme8을 사용합니다.
PIM_PRECISION FP16, INT8, FP32 중 하나를 선택합니다.
디버그 플래그 DEBUG_CMD_TRACE, DEBUG_PIM_TIME, PRINT_MEM_TRACE 등을 켤 수 있습니다.

8. 출력 결과는 어떻게 읽는가

테스트 실행 시 보이는 핵심 수치는 보통 다음과 같습니다.

  • Cycle - 시뮬레이션 사이클 수
  • Speed-up - PIM 사용 전후 성능 개선 비율
  • PASS/FAIL - 기대 정확도 충족 여부

예를 들어 성능 벤치마크는 이런 형태로 나옵니다.

> Performance Test
  GEMV (PIM disabled)
> Test Results
> Cycle : 36082

  GEMV (PIM enabled)
> Test Results
> Cycle : 13166

> Speed-up : 2.74054

9. 자주 만나는 문제와 대처

문제: ./sim: No such file or directory
대처: 아직 빌드가 안 됐거나, 현재 폴더가 프로젝트 루트가 아닙니다. 먼저 scons를 실행하고 루트 폴더에서 다시 시도합니다.
문제: gtest 관련 링크 에러
대처: libgtest-dev 설치 여부를 확인하고, 시스템에 맞는 빌드 환경인지 살펴봅니다.
문제: PIM 테스트가 기대와 다르게 실패함
대처: 먼저 system_hbm.ini가 기본값인지 확인하고, 디버그 플래그를 줄여서 다시 실행합니다.
주의: 디버그 출력을 너무 많이 켜면 로그가 길어져서 원인을 보기 어려워집니다. 처음에는 출력 옵션을 최소로 두는 편이 좋습니다.

10. 처음 배우는 사람에게 추천하는 학습 순서

  1. 먼저 README.md와 system_hbm.ini를 훑어서 큰 그림을 잡는다.
  2. ./sim --gtest_list_tests로 실행 가능한 테스트를 확인한다.
  3. PIMKernelFixture.gemv를 실행해 기능이 돌아가는지 본다.
  4. src/tests/PIMKernel.cpp를 읽으면서 실행 순서를 따라간다.
  5. 그다음 src/PIMCmd.*, src/MemorySystem.*, src/PIMRank.* 순으로 내려간다.
이 순서로 가면 “돌리는 법”과 “작동 원리”를 분리해서 익힐 수 있어서 훨씬 덜 헷갈립니다.

./sim --gtest_list_tests
./sim --gtest_filter=PIMKernelFixture.gemv
./sim --gtest_filter=PIMKernelFixture.mul
./sim --gtest_filter=PIMKernelFixture.add
./sim --gtest_filter=PIMKernelFixture.relu
./sim --gtest_filter=PIMBenchFixture.gemv

마무리

이 시뮬레이터는 UI를 눌러 조작하는 도구가 아니라, 테스트를 골라 실행하고 결과를 콘솔로 확인하는 연구용 모델입니다. 처음에는 gemv 하나만 성공적으로 돌려도 충분하고, 그다음에 설정과 구조를 조금씩 넓혀가는 방식이 가장 편합니다.
