2.1 GR00T workload를 먼저 고정

GR00T 전체 inference를 PCU에서 실행하지 않았다. 프로젝트 대상은 정규화이므로 실제 모델 코드와 inventory에서 LayerNorm·RMSNorm·AdaLayerNorm의 shape와 호출 분포를 추출하고, action-head에는 실제 BF16 activation trace를 사용했다.

  • LayerNorm/AdaLayerNorm: action-head 1536·2048-wide 실제 BF16 trace
  • RMSNorm: GR00T inventory에서 확인한 128·2048-wide shape에 대한 대표 BF16 vectors
  • 모든 경우: bank mapping → reduction → scalar/rsqrt → replay/apply → write-back 전체 경로 검증

2.2 산술 정확도를 먼저 잠금

입출력과 저장은 BF16으로 유지하되, 오차가 누적되는 reduction·variance·rsqrt Newton iteration·affine 연산은 FP32로 수행하고 마지막에 BF16 RNE로 좁혔다. 정확도가 고정된 뒤에만 lane과 buffer 구조를 바꿨기 때문에, 성능 개선이 산술 근사 악화에서 온 것이 아니다.

2.3 분석 모델과 RTL을 반복 교정

cycle model에는 bank read/write 정책, global reducer single-in-flight, RMS/Layer scalar latency, context depth, replay handoff를 반영했다. 대표 5개 RTL 측정과 오차가 ±3% 이내가 되도록 검증 gate를 만들고 자동 단위 시험으로 고정했다.

3. 최적화에 사용한 핵심 아이디어

아이디어 A — memory traffic의 경계를 분리해 계산채택

bank 내부에서 activation을 두 번 읽는 것은 비용이지만, 외부 GPU/HBM interface로 tensor 전체를 왕복하는 것과 같지 않다. 따라서 external bytes, bank-array read/write bytes, bank↔logic statistic bytes를 별도로 계수했다.

  • PCU resident-affine 조건에서 외부 I/O 감소율: 약 99.99%
  • 이 분리 덕분에 “회로가 늘어도 외부 I/O를 줄이는가”라는 프로젝트 목적을 올바르게 평가할 수 있었다.
아이디어 B — 실제 bank bandwidth를 반영한 split-R/W scheduler채택

기존 독립 ready/valid 포트는 reduction과 replay가 같은 bank를 동시에 읽을 수 있다고 낙관했다. 최종 RTL에서는 두 read가 하나의 slot을 공유하고, write-back은 별도 backpressured path로 배출하게 했다.

  • reduction/replay: fair round-robin
  • write-back: read와 동시 진행하여 output FIFO를 우선 drain
  • 16-bank lockstep: partial bank valid는 먼저 소비하지 않음
  • age counter와 optional single-shared mode로 starvation 방지
아이디어 C — bank 공급률 하한으로 lane 수 선택8-lane 채택

“4-lane이 싸다”와 “16-lane이 빠르다” 사이를 감으로 선택하지 않았다. 256-bit bank word에서 최소 한 개의 128-bit slice를 매 active bank cycle에 처리한다는 50% 하한을 정의했다.

후보bank당 폭공급률판정
4-lane64 bit25%하한 FAIL
8-lane128 bit50%최소 PASS
16-lane256 bit100%비용 과다
아이디어 D — multi-row overlap과 bounded look-ahead채택

row n+1 reduction, row n scalar, row n−1 apply/write-back을 겹치되 reduction이 너무 앞서가 replay를 굶기지 않도록 top context를 8개로 제한했다. context 감소가 단순 비용 절감뿐 아니라 scheduling throttle로 작동했다.

  • 280×2048: 9532 → 9017 cycles
  • 41×1536: 1120 → 1065 cycles
  • context comparator/mux fan-in과 state도 함께 감소
아이디어 E — 병목이 아닌 자원은 늘리지 않음비용 억제

local reducer context 2→4, scalar engine 추가, FIFO 축소/증설 등을 각각 실제 RTL로 측정했다. “더 병렬이면 더 빠르다”는 가정을 사용하지 않고 cycle 개선이 없는 자원 증가는 기각했다.

아이디어 F — control/state 비용과 조합 loop 정리채택
  • traffic counter 내부 폭 64→32 bit: 6개 counter에서 192 state bits 절감
  • scalar request-ready ↔ response-ready 조합 되먹임 제거: Verilator UNOPTFLAT 1→0
  • 외부 counter interface는 64-bit zero extension으로 호환 유지

냉정한 해석: 현재 RTL을 다시 처음부터 설계할 이유는 없다. 다만 실제 memory controller가 split read/write를 제공하지 않고 완전 single-port라면 scheduler parameter와 시스템 cycle 판정을 다시 해야 한다. 산술 datapath와 8-lane 선택까지 모두 폐기하는 상황은 아니다.
