Normalization HBM Boundary Adapter 구현 보고서

동결된 8-lane 정규화 PCU의 reduction·replay·write-back transaction을 기존 DRAM simulator의 ACT/RD/WR/PRE command와 연결하기 위해 새로 설계한 boundary adapter의 아이디어, 구현 과정, 디버깅, 최적화 및 검증 결과를 정리한다.

최종 판정: 기존 bank-side PIM adapter는 직접 재사용하지 않는다. DRAM timing/bank 모델만 재사용하고 정규화 전용 command/credit adapter를 새로 구현하는 것이 맞다. simulator용 구현은 완료됐으며, production HBM 내부 규격이 확정되면 command/credit front-end를 교체한다.

1. 왜 새로운 어댑터가 필요한가

재사용dram_bank_array_model

open-row 상태, command legality, tRCD/tCCD/tRAS/tRP/tWR 등의 timing rule과 read response 동작.

신규 설계normalization_hbm_boundary_adapter

PCU transaction 패킹, 주소 매핑, command FSM, read-credit 관리, replay 공급, write coalescing.

직접 재사용 불가기존 combinational PIM read 경로

response credit·backpressure·write-back이 없고 새 PCU의 all-bank transaction 구조와 맞지 않는다.

즉, PCU RTL을 바꿨기 때문에 DRAM 자체를 다시 만드는 것이 아니라, PCU와 DRAM 사이의 의미 변환 계층을 새로 만든 것이다.

3. 핵심 설계 아이디어

128↔256-bit 패킹

PCU bank vector는 8×BF16=128 bit, DRAM word는 256 bit다. 짝수 vector는 lower half, 홀수 vector는 upper half에 저장해 word 하나를 두 번 활용한다.

Open-row column layout

x, affine, output을 서로 다른 row가 아니라 같은 physical row의 column 구간에 배치해 phase마다 PRE/ACT하는 비용을 제거한다.

X slice reuse

한 번 읽은 256-bit x word를 연속 두 reduction/replay vector에 사용한다.

Affine packing

gamma는 [127:0], beta는 [255:128]에 저장해 operand 두 개를 RD 하나로 공급한다.

Write coalescing

PCU output 두 개를 256-bit word로 조립한 뒤 WR 하나로 기록한다. 홀수 개의 마지막 vector는 byte mask로 나머지 절반을 보존한다.

All-bank atomicity

16개 bank가 모두 valid/ready일 때만 PCU vector를 이동시켜 row alignment와 tag 일관성을 보존한다.

Credit-aware issue

read acceptance부터 response retirement까지 outstanding을 1로 제한하고 테스트에서도 peak=1, final=0을 assertion한다.

Held replay request

PCU의 scalar 계산 완료 후 replay 요청을 backpressure 아래에서도 잃지 않고 수락한다.

5. 구현 과정

1단계 · 기존 구조 감사
DRAM command encoding, timing legality, response hold, PIM combinational read path를 조사했다. 기존 PIM adapter에는 정규화 replay/write-back과 credit 계약이 없음을 확인했다.
2단계 · 인터페이스와 주소 매핑 확정
PCU의 reduction/replay/write-back 포트를 직접 연결하고, descriptor에 row와 x/affine/output base column을 넣었다. 2048 hidden이 정확히 32 columns에 들어가는 layout을 정했다.
3단계 · command FSM 구현
ACT, reduction fetch, replay fetch, output assembly/WR, PRE를 직렬화하고 DRAM legality-ready 방식에 맞춘 valid pulse를 구현했다.
4단계 · 실제 PCU–DRAM 통합
산술 PCU와 DRAM 모델을 동시에 instantiation한 testbench를 만들고 LayerNorm/RMSNorm의 output memory를 직접 검사했다.
5단계 · 오류 수정
write-back 조합 순환과 output column off-by-one을 발견해 ready 생성과 completed-vector 주소 계산을 수정했다.
6단계 · command 최적화
queue depth를 늘리는 대신 x word reuse, affine packing, write coalescing, same-row layout으로 실질적인 command 수를 절반으로 줄였다.
7단계 · 완료 감사
4개 통합 case, 4개 abstract baseline, timing/credit assertions, command count, memory output, Yosys check를 자동 대조했다.

8. 최종 구조 판단

현재 병목: PCU arithmetic 또는 adapter queue depth가 아니라, 단일 shared command/data path와 outstanding read credit 1이다. 2048 LayerNorm에서 channel payload는 약 46.7 bit/cycle로 tCCD 기반 64 bit/cycle 상한의 약 73%를 사용하지만, 이를 16 banks가 직렬로 나눠 가진다.

PCU scheduler를 바꾸지 않은 이유

  1. 8-lane 선정 기준은 active bank transfer cycle에서 128-bit slice를 소비하는 것이며 adapter도 해당 폭을 정확히 전달한다.
  2. 현재 DRAM port는 host-style shared channel이지 목표로 하는 logic-die 내부 bank-to-PCU fabric의 확정 규격이 아니다.
  3. 기존 GR00T trace에서 8-lane은 4-lane보다 약 1.9배 빠르고, 16-lane은 비용과 timing 손실이 과다했다.
  4. shared host bus만 보고 lane을 줄이면 향후 bank-parallel 내부 fabric에서 계산 성능을 잃는다.
