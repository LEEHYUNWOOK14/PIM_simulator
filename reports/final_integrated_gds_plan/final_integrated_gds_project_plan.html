1. 프로젝트 목표 재정의

최종 목표: 최종 통합 GDS 통합 normalization RTL을 실제 표준셀로 배치·배선한 GDS와 TSV, micro-bump, HBM floorplan overlay를 동일 좌표계에서 병합한 단일 결과물을 만든다. 결과는 논문 그림, 구조 검토, 재현성 검증과 후속 열·비용 분석에 사용한다.
제조용 signoff 목표 제거 Tape-out 승인, foundry signoff와 제조 인계는 이 계획의 작업·완료 조건·일정에서 제외한다. 단, 최종 파일이 제조용이 아니라는 표시는 오해 방지를 위해 유지한다.
최종 파일의 권장 명칭: STOB_PIM2_FINAL_INTEGRATED_RESEARCH_GDS
“Final”은 이 연구 프로젝트의 최종 산출물이라는 뜻이며, 제조 승인 또는 tape-out 준비 완료를 뜻하지 않는다.

2. 현재 작업 상황

RTL·합성 PASSPF-0~PF-2 완료
배치 PASSPF-3, 최종 위반 0
전역 배선 FAILPF-4, v4 혼잡 잔존
v5 실행 중bank-aware 재배치 기반
현재 병목: v4 전역 배선은 route guide와 congestion report를 생성했지만 상세 혼잡 위반 5,998건과 CuGR 잔여 혼잡 2,620이 남았다. v5는 4×4 bank-aware 배치와 분산 패드를 적용해 이를 낮추는 중이다. OpenROAD는 확인 시점에 약 23.7GB RSS와 WSL 메모리 약 82.5%를 사용했다.

v5 입력 배치는 약 484만 개 movable cell을 합법화했으며 최종 배치 위반은 0건이다. 다만 현재 v5 스크립트는 전역 배선 guide와 congestion report만 생성하고 상세 배선 DB나 GDS는 생성하지 않는다.

5. 단계별 실행 계획

Phase A — v5 결과 판정과 PF-4 해결

현재
  • 실행 중인 v5를 중복 실행하지 않고 종료 상태, peak memory, exit code를 수집한다.
  • v5 congestion report에서 총 위반, 잔여 혼잡, 최대 overuse, hotspot을 v4와 동일 정의로 비교한다.
  • 0이 아니면 bank region, pin 분산, utilization, routing layer와 high-fanout 예외를 한 변수씩 변경한다.
  • PF-4 validator가 자동으로 새 revision을 선택하고 해시 일관성을 확인하도록 collector를 갱신한다.

Phase B — GDS로 이어지는 physical flow 고정

PF-4 이후
  • 현재 전역 배선 스크립트에 routed ODB 저장과 재시작 지점을 추가한다.
  • 315,739 terminal의 clk_i를 단순 skip한 상태로 최종화하지 않고, CTS 또는 명시적 연구용 clock distribution 모델을 적용한다.
  • 클록 반영 후 placement legality와 global-route overflow를 다시 확인한다.
  • 모든 입력 RTL, Liberty, LEF, SDC, ODB의 SHA-256을 하나의 revision manifest에 고정한다.

Phase C — 상세 배선과 RTL GDS

대기
  • 상세 배선 전 WSL memory/swap과 출력 경로 여유 공간을 사전 점검한다.
  • checkpoint 기반으로 detailed route를 실행하고 중간 진행률, 메모리, violation 수를 보존한다.
  • 상세 배선이 terminal completion에 도달해야 RTL GDS 생성 단계로 진행한다.
  • 남은 DRC·antenna·timing 수치는 숨기지 않고 최종 보고서에 정량 기록하되, 제조 signoff closure 작업으로 확장하지 않는다.
  • OpenROAD stream-out 후 KLayout으로 top cell, hierarchy, bbox, 사용 layer와 non-empty geometry를 독립 확인한다.

Phase D — TSV·micro-bump 통합

대기
  • 기존 floorplan manifest와 overlay GDS를 최신 RTL revision에 맞춰 재생성한다.
  • RTL GDS와 overlay의 DBU, 방향, 원점, die bbox를 확인하고 두 개 이상의 anchor로 변환을 결정한다.
  • 레이어 충돌은 자동 remap하되 recipe에 명시하고 사람이 검토할 수 있도록 남긴다.
  • 입력 해시가 바뀌면 병합을 거부하는 hash-pinned recipe로 최종 GDS를 생성한다.

Phase E — 최종 감사와 종료

마지막
  • 새 프로세스에서 최종 GDS를 다시 열어 top, cell 수, layer, bbox, RTL/overlay shape 존재를 확인한다.
  • 고정 카메라 KLayout PNG와 구조 요약을 만들어 사람이 육안으로 좌표·방향을 검토한다.
  • 모든 입력·출력의 SHA-256, 생성 명령, tool version과 결과 분류를 manifest에 기록한다.
  • evidence matrix에서 RTL GDS는 placed/routed research artifact, overlay는 illustrative로 분리한다.
  • M0~M8 결과와 알려진 제한을 최종 HTML에 기록하고 프로젝트를 종료한다.

6. 프로젝트 완료 정의

① 통합 RTL GDS 존재
현재 통합 normalization revision에서 생성되고 독립적으로 다시 열리는 GDS가 있다.
② 물리 배선 추적 가능
상세 배선 완료 ODB, route report와 GDS가 같은 revision hash로 연결된다.
③ Overlay 정렬 검증
TSV·bump overlay가 최소 2개 anchor와 단위 변환 검사를 통과한다.
④ 단일 최종 파일
RTL과 overlay geometry가 모두 존재하는 merged_final_physical.gds가 생성된다.
⑤ 재현 가능
깨끗한 출력 폴더에서 문서화된 명령으로 recipe·GDS·검증 보고서를 다시 만들 수 있다.
⑥ 주장 경계 일치
남은 timing/DRC/antenna 제한과 illustrative overlay가 evidence matrix와 최종 보고서에 동일하게 기록된다.

완료를 막지 않는 항목: 제조용 foundry signoff, tape-out 승인, proprietary HBM PHY 검증은 프로젝트 완료 조건이 아니다. 그러나 detailed route 자체의 terminal completion과 최종 GDS의 구조적 유효성은 반드시 충족해야 한다.

7. 주요 위험과 대응

메모리 부족

전역 배선만으로 약 23.7GB를 사용 중이다. 중복 OpenROAD 실행 금지, 충분한 swap 확보, checkpoint 저장, 상세 배선 단독 실행으로 대응한다.

혼잡이 0으로 내려가지 않음

단순 router 반복보다 bank locality, pad 분산, utilization과 wide-interface 구조를 우선 수정한다. 변경 변수와 효과를 한 번에 하나씩 기록한다.

클록이 실제 배선에서 제외됨

현재 high-fanout clock skip은 최종 GDS 조건으로 인정하지 않는다. CTS/clock distribution 이후 전체 배선 결과를 다시 생성한다.

RTL과 overlay 좌표 불일치

눈대중 이동·확대는 금지한다. DBU=물리 스케일을 분리하고 최소 2개 anchor와 die-boundary 검사를 사용한다.

오래된 산출물 혼입

B0 GDS, 과거 output/output.gds, historical merge stress 결과를 현재 최종 입력으로 재사용하지 않는다. 입력은 hash-pinned current revision만 허용한다.

“최종” 표현의 오해

파일명과 보고서에 RESEARCH 및 NOT_FOR_FABRICATION 표식을 넣고 evidence 등급을 함께 제공한다.
