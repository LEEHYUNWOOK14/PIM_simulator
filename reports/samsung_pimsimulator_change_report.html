2. C++ 시뮬레이터에서 바뀐 점

2.1 Logic Die 스케줄링 모델

LogicDieScheduler가 단순 예약 계산을 넘어 command/epoch/channel 문맥을 추적합니다. epoch·ordinal·signature가 같은 명령은 채널 mask로 합쳐(coalescing) dispatch overhead를 줄이고, 기대 채널 mask가 완성된 경우에만 발행 가능한 상태로 다룹니다. 예약 결과에는 queue, compute, transfer, service, completion delay 및 dispatch overhead가 분리 기록됩니다.

2.2 유한 큐와 backpressure

실제 하드웨어에 대응하도록 source FIFO 및 중앙 ready queue의 유한 용량을 고려하는 경로가 추가되었습니다. LOGIC_PCU_QUEUE_DEPTH 설정으로 기존 무제한 동작과 유한 큐 동작을 구분하며, queue stall/full event 및 stream별 headroom을 측정합니다. 실험 문서의 대표 구성은 32 PCU, 중앙 큐 64, stream별 source depth 8입니다.

2.3 계층 중재 및 MobileNetV4 검증

bank-side와 logic-die 요청 사이의 BANK_PRIORITY, LOGIC_PRIORITY, ROUND_ROBIN, READY_BYPASS 정책을 검증하는 테스트가 추가되었습니다. MobileNetV4 UIB workload에는 FP16 결과 hash, hierarchy arbitration microbenchmark, miniature end-to-end smoke 경로가 포함됩니다.

3. RTL 아키텍처 변경

시뮬레이터의 기능 계약을 합성 가능한 RTL 구조로 확장했습니다. 핵심 데이터 흐름은 다음과 같습니다.

DRAM command → bank/row model → bank-side PIM → local reduction → channel arbitration/TSV → logic-die operand context → coalescer/epoch barrier → 최대 16-PCU scheduler → result router/reduction

구성변경 내용
Bank-side PIM2개 DRAM bank를 하나의 PIM block으로 묶고 CRF lockstep 실행, GRF/SRF 및 FP16·INT8 arithmetic 경로 구현
DRAM behavioral modelACT/RD/WR/PRE/REF와 tRCD/tRAS/tRP를 반영하는 유한 bank/row/column 모델 추가. 실제 DRAM cell 합성이 아닌 검증용 모델
Logic-die pipeline128-entry broadcast-mask coalescer, epoch barrier, channel별 operand context, 16-PCU issue wave 및 고정 issue-port 매핑 구현
연결·결과 처리두 개의 독립적으로 stall 가능한 256-bit TSV lane, shared buffer, cross-channel reduction 및 result retirement 경로 구현
안정성ready/valid handshake, 출력 backpressure 중 결과 유지, valid/pointer/control만 reset하여 메모리 추론을 고려

6. 해석상 주의점

현재 결과는 삼성 PIMSimulator의 기능적 기준을 보존하면서 하드웨어 구현 세부를 추가한 연구·검증 모델입니다. HBM2 PHY/vendor macro, 실제 DRAM cell, full-chip STA/CDC/DFT 및 tape-out signoff까지 완료되었다는 의미는 아닙니다. 또한 현재 작업 트리의 신규 산출물과 로그가 모두 Git에 포함되어 있어, 최종 제출 전에는 재현성에 필요한 파일과 임시 산출물을 분리하는 것이 좋습니다.
