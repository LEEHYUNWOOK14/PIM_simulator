GR00T RMSNorm 프로파일이 표준 연산인가, 튜닝 연산인가?

작성일: 2026-08-11 · 대상: STOB_PIM2 및 STOB_PIM_pure_layornorm · 목적: 범용 PIM 아키텍처 평가에 사용된 RMSNorm 프로파일의 성격 판정

핵심 결론
현재 GR00T RMSNorm 프로파일은 수식과 알고리즘이 튜닝된 RMSNorm이 아니라 표준 RMSNorm이다. 다만 GR00T의 실제 구조에서 유도한 shape·epsilon·affine 여부·호출 횟수를 사용해 워크로드 수준으로 특화된 프로파일이며, 시뮬레이터에서는 표준 RMSNorm 전체가 아니라 element-wise MUL 단계만 PIM에서 실행한다. reduction, mean-square, rsqrt, scale 생성은 host에서 수행되고 그 시간은 측정 cycle에 포함되지 않는다.

1. 기존 RMSNorm의 정의

RMSNorm은 평균을 빼지 않고 입력 벡터의 root mean square로 정규화한다. 한 row의 hidden dimension을 d라 하면 다음과 같다.

rms(x) = sqrt((1/d) * SUM_i x_i^2 + epsilon)
y_i = x_i / rms(x) * w_i

w는 학습된 affine weight다. 핵심 순서는 SUMSQ reduction → 평균 제곱 → epsilon → reciprocal square root → element-wise multiply이며 평균 제거가 없다는 점이다. 이 정의는 RMSNorm 원 논문과 PyTorch 공식 문서에 근거한다 [W1][W2].

2. 현재 GR00T RMSNorm 구현

입력 x, weight gamma 생성
  -> Bank-PIM MUL: x^2
  -> host: row별 SUMSQ / hidden_size
  -> host: 1 / sqrt(mean_square + epsilon)
  -> host: scale = gamma * inv_rms
  -> Bank-PIM MUL: x * scale
  -> 출력

로컬 runRmsNorm()은 첫 번째 PIM 연산으로 입력 자기 자신을 곱하고, 두 번째 PIM 연산으로 입력과 host가 만든 scale을 곱한다 [L1]. 따라서 x^2와 x*gamma*inv_rms의 element-wise 부분은 표준 RMSNorm과 일치한다.

3. 순정 연산인가, 튜닝 연산인가?

항목현재 GR00T 프로파일판정
정규화 수식x / sqrt(mean(x^2)+epsilon) * gamma표준 RMSNorm

논문에서 “GR00T RMSNorm을 가속했다”고만 쓰면 부정확하다.
정확한 표현은 “GR00T-derived RMSNorm workload의 Bank-PIM element-wise phases를 평가했다” 또는 “host reduction/rsqrt를 제외한 PIM portion을 평가했다”이다. 전체 정규화 latency를 주장하려면 reduction·rsqrt·동기화·traffic을 포함해야 한다.

3-1. epsilon의 의미와 결정 방식

epsilon은 RMSNorm 수식에 반드시 들어가는 안정화 항이지만, 모든 RMSNorm 구현이 동일한 숫자를 사용하는 것은 아니다. 현재 GR00T 프로파일의 1e-6은 “RMSNorm의 보편적 표준값”이 아니라 Qwen3-VL 경로의 모델 설정값이다. 따라서 GR00T 재현 실험에서는 1e-6을 유지하고, 범용 아키텍처 실험에서는 1e-6·1e-5·dtype-dependent default를 sensitivity 대상으로 비교해야 한다.

하드웨어가 epsilon을 runtime input으로 받는 구조는 연구자가 매번 결과에 맞춰 epsilon을 조정한다는 뜻이 아니다. 모델 설정 또는 소프트웨어 컨트롤러가 정한 epsilon을 normalization request에 넣어 하드웨어로 전달한다는 뜻이다. 현재 RTL 인터페이스에는 normalization_epsilon_i 입력이 있다 [L3].

모델 config / 소프트웨어 컨트롤러
        |
        +-- epsilon = 1e-6 (GR00T/Qwen3-VL)
        +-- epsilon = 다른 모델의 설정값
        |
        +-- normalization_epsilon_i
                |
          RMSNorm hardware

따라서 연구자가 새 epsilon 결정 알고리즘을 만들 필요는 없다. 연구자가 해야 할 일은 모델별 epsilon을 정확히 전달하고, 여러 epsilon에서 정확도·수치 안정성·cycle·area/power sensitivity를 검증하는 것이다. epsilon을 출력이 맞을 때까지 임의로 조정하는 방식은 재현 가능한 실험이 아니며 보고서에서 피해야 한다.

4. GR00T에서 프로파일링한 RMSNorm 구조

로컬 분석은 GR00T N1.7의 Qwen3-VL text 경로를 대상으로 한다. decoder layer마다 다음 네 종류를 계산 대상으로 잡았다 [L2][W3].

구성shapeepsilon호출 수축
input RMSNorm[280, 2048]1e-632hidden 2048
post-attention RMSNorm[280, 2048]1e-632hidden 2048
query RMSNorm[8960, 64]1e-632head dim 64
key RMSNorm[8960, 64]1e-632head dim 64

총 64회는 16개 decoder layer × 4개 RMSNorm으로 계산됐다. Q/K의 [8960,64]는 280 × 32 heads를 row 방향으로 펼친 것이다. 로컬 기록은 초기 32회 추정에서 Q/K RMSNorm을 누락한 것을 공식 Transformers 구현 확인 후 64회로 수정했다고 명시한다 [L2].

5. GR00T RMSNorm 정규화 데이터패스

각 row x[0:d-1]
       |
       +-- Bank-PCU: x_i * x_i --+
                                  |
                    row SUMSQ reduction (현재 프로파일은 host)
                                  |
                    mean_square = SUMSQ / d
                                  |
                    a = mean_square + epsilon
                                  |
                    inv_rms = rsqrt(a) = 1 / sqrt(a)
                                  |
       +-- scale_i = gamma_i * inv_rms (현재 host 생성)
       |
       +-- Bank-PCU: y_i = x_i * scale_i
                                  |
                           normalized output y

현재 STOB_PIM2 RTL에는 이 분석을 확장한 normalization sideband가 별도로 존재한다. bank partial SUM/SUMSQ를 logic die로 보내고, logic die에서 global accumulation·LayerNorm/RMSNorm finalize·LUT256 RSQRT를 수행한 뒤 inv-RMS 또는 inv-std를 broadcast하는 방향이다 [L3]. 그러나 저장소 문서도 이 sideband와 전체 normalization 완료를 동일시하지 말라고 명시하므로, 기존 GR00T 프로파일과 RTL 확장 결과는 분리해야 한다.

623,040은 GR00T 전체 inference의 RMSNorm 총 latency가 아니다. 2개의 unique shape를 한 번씩 실행한 Bank-PIM cycle을 공식 호출 횟수에 외삽한 값이며, host 단계와 실제 pretrained activation은 포함하지 않는다 [L2][L4].

7. 범용 아키텍처 평가 권고

  1. 명칭을 분리한다. “GR00T-derived RMSNorm element-wise profile”과 “general RMSNorm latency”를 구분한다.
  2. shape sweep을 추가한다. hidden size 64, 128, 256, 512, 1024, 2048, 4096, 8192와 여러 row 수를 사용한다.
  3. full path를 포함한다. Bank partial SUMSQ → cross-bank reduction → divide → epsilon → rsqrt → broadcast → final multiply의 cycle·traffic·queue delay를 breakdown한다.
  4. dtype를 분리한다. GR00T checkpoint의 BF16 경로와 현재 FP16 simulator 경로를 같은 결과로 합치지 않는다.
  5. 입력을 보강한다. synthetic input 외에 실제 checkpoint activation 또는 공개 가능한 representative activation 통계를 사용한다.
  6. RSQRT를 명시한다. RTL의 LUT256은 정확한 software rsqrt가 아니라 근사 하드웨어 후보이므로 정확도·면적·latency trade-off를 별도 보고한다.

8. 최종 판정

연산 정의: GR00T 프로파일은 순정 표준 RMSNorm이다. 평균을 빼지 않고 mean-square 기반 inverse RMS를 곱하며 학습 weight를 적용한다.

워크로드: GR00T N1.7/Qwen3-VL의 shape, epsilon, affine, layer 수와 호출 수에 맞춘 특화 프로파일이다.

하드웨어: 순정 RMSNorm 전체가 아니라 square와 final scale multiply를 Bank-PIM으로 보내고 reduction/rsqrt를 host로 남긴 분할 실행 모델이다. 범용 아키텍처의 최종 근거로 사용하려면 full-path normalization 모델을 추가해야 한다.
