이 저장소의 주 설계 흐름은 PIMSimulator/DRAMSim2 기반 아키텍처 시뮬레이션, Icarus Verilog 기반 SystemVerilog 기능 검증, Yosys/ABC 합성, OpenROAD-flow-scripts와 OpenROAD 기반 Sky130HD 물리 구현, KLayout 기반 GDS 검사·시각화로 구성된다. Python은 벡터 생성, 결과 수집, workload 모델, 전력·열·3D 변환을 잇는 공통 자동화 계층이다.
상태 표기: 실행 증거 있음은 저장소 로그·manifest에서 실제 실행이 확인된 도구, 연동/선택 경로는 스크립트나 문서에 인터페이스가 있으나 현재 호스트 실행 증거가 제한적인 도구, 지원 인프라는 직접 EDA 엔진이 아닌 빌드·검증 기반을 뜻한다.

8. 결론과 해석 경계

이 저장소는 오픈소스 중심의 완결된 연구용 digital design flow를 갖고 있다. 기능 및 cycle-level 검증은 PIMSimulator와 Icarus, 합성은 Yosys/ABC, 물리 구현은 ORFS/OpenROAD/Sky130HD, GDS 검사는 KLayout이 담당한다. Python 기반 workload·power·thermal·3D 도구가 이들 산출물을 연결한다.

다만 도구가 존재하거나 실행된 사실과 설계가 signoff를 통과했다는 사실은 다르다. 현재 저장소의 physical 결과에는 congestion, detailed-route DRC, timing 및 OOM 실패 기록이 포함되어 있다. 따라서 이 툴 체인은 연구·비교·feasibility 검증용이며, foundry signoff, LVS/DRC clean, IR/EM closure 또는 tapeout readiness를 자동으로 의미하지 않는다.

본 보고서는 조사 당시 동시 작업 중인 저장소를 대상으로 작성되었다. 기존 변경 파일은 수정하지 않았으며, 새 산출물은 이 HTML 파일과 상위 REPORT/ 디렉터리뿐이다. 버전 정보는 실행 결과별 manifest를 우선하며, GCP와 과거 desktop/WSL 산출물의 버전 차이를 의도적으로 분리해 기록했다.
